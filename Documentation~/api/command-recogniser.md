# VoxrCommandRecogniser

`public class VoxrCommandRecogniser : MonoBehaviour` -- Namespace: `VoXR.Commands`

Subscribes to speech events and runs text through the command parser pipeline: pattern matching, confidence/score thresholds, utterance buffering, sequential extraction, and debounce.

## Inspector Fields

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `speechRecogniser` | `VoxrSpeechRecogniser` | -- | Reference to the speech recogniser component |
| `minConfidence` | `float` | `0.4` | Minimum per-word confidence to accept a command. This is the *minimum* over the matched span, not the average, so one weak word vetoes the command. Commands with confidence below this are rejected. `-1` (no data) bypasses this check. See [the two gates](../scoring.md#5-the-bar-and-the-two-gates) for how repeated words resolve and what `-1` really means. |
| `minScore` | `float` | `0.6` | Minimum pattern match score (0.0--1.0) to accept a command. See [the score formula](../scoring.md#1-the-score-formula) for what produces that number and [the two gates](../scoring.md#5-the-bar-and-the-two-gates) for tuning it against `minConfidence`. |
| `coverageWeight` | `float` | `1.0` | How much each in-grammar word a match leaves unexplained counts against the score — both those skipped before it and those left over after it (#65 §5.2). Charged *during* candidate selection, so it decides which pattern wins, not merely whether the winner clears `minScore`. At `1.0` the score is close to the fraction of the utterance the pattern covers. `0` disables it, which also switches off the #42 protection. Consumed when the parser is built, so a change takes effect at the next `RebuildParser` / `Configure` / `SetActiveSets` / `NotifySlotChanged` — not on the next utterance. Named `skippedWordPenalty` before #65: a value set on the component itself migrates via `[FormerlySerializedAs]`, but that attribute governs a field's own serialized data, so a prefab-**instance** override of the old name is stored as a literal property path and may not carry over — re-check any prefab that overrode it. See [Coverage](../command-recognition.md#coverage) for the summary and [Matching and Scoring](../scoring.md#2-coverage) for the full rule. |
| `bufferWindow` | `float` | `0.5` | Seconds to buffer consecutive VOSK results before parsing. Merges speech split by mid-command pauses. `0.5` matches typical PC latency; raise it on Quest 3 (see [troubleshooting](../troubleshooting.md#commands-split-across-two-results)). |
| `eagerFlushOnCompleteMatch` | `bool` | `false` | Fire a complete command immediately when the buffered speech can't be extended or completed by more words, instead of waiting out `bufferWindow`. Commands that are a prefix of a longer one, or whose trailing slot could still grow, keep waiting — as does a buffer that fits two *different* intents equally and differs at one required word, where committing early would fire a coin flip, and one whose winning candidate missed its own [first required element](../scoring.md#the-leading-required-miss-bar). See [Eager flush](../command-recognition.md#eager-flush-low-latency-complete-commands) and [the eager-flush verdicts](../scoring.md#6-eager-flush-verdicts). |
| `prefixHoldSeconds` | `float` | `0` | How long a *complete but still extendable* command (a prefix of a longer one, a trailing slot that could grow, or any complete match in a grammar too complex for the eligibility analysis) waits for the continuation before firing, instead of the full `bufferWindow`. `0.5`--`0.8` is usually enough. Requires `eagerFlushOnCompleteMatch`; never lengthens the wait; `0` keeps the full window; never armed for a winner [barred](../scoring.md#the-leading-required-miss-bar) for missing its first required element, which waits the full `bufferWindow`. See [Prefix hold](../command-recognition.md#prefix-hold-shortening-the-ambiguous-wait). |
| `commandCooldown` | `float` | `0.3` | Per-intent debounce window in seconds. Suppresses duplicate firings of the same intent within this period. |
| `freeSpeechMode` | `bool` | `false` | When true, disables grammar constraint for unconstrained vocabulary with best-effort command matching |
| `slotAssets` | `VoxrSlotAsset[]` | -- | Slot definitions for Inspector authoring. May be left empty — an all-literal grammar declares no slots and converts with zero of them |
| `commandSetAssets` | `VoxrCommandSetAsset[]` | -- | Command set definitions for Inspector authoring. This is the list that must be populated: empty leaves `Awake()` nothing to convert, and it warns when `slotAssets` was populated. See [Wire assets onto VoxrCommandRecogniser](../inspector-authoring.md#4-wire-assets-onto-voxrcommandrecogniser) |
| `initialActiveSetNames` | `string[]` | -- | Which sets to activate on startup when using Inspector authoring |
| `pendingTimeout` | `float` | `5.0` | Maximum seconds a pending command waits for follow-up speech before timing out. The window restarts each time follow-up speech fills a required slot, and again when a filled command re-enters pending for confirmation — so it bounds *silence*, not the whole exchange |
| `pendingTimeoutBehavior` | `VoxrPendingTimeoutBehavior` | `Cancel` | What happens on timeout: `Cancel` discards the command, `FireAsIs` fires it with whatever slots were filled. `FireAsIs` can only deliver an *incomplete* command when that command also sets `allowPartialMatch` — see [the two deliberate exceptions](../command-recognition.md#the-two-ways-an-incomplete-command-still-fires). **`FireAsIs` does not apply to a disambiguation**: there the *intent* is unknown rather than the arguments, so firing the first-registered candidate after a pause is the same coin flip, merely later. An unanswered ambiguity always cancels |
| `confirmVocabulary` | `string[]` | -- | Phrases that confirm a pending command. Empty = defaults ("confirm", "affirmative", "yes", "go ahead", "do it"). |
| `cancelVocabulary` | `string[]` | -- | Phrases that cancel a pending command. Empty = defaults ("cancel", "abort", "negative", "belay that", "never mind"). |
| `disambiguateSiblingTies` | `bool` | `false` | When the recogniser cannot tell two commands apart — they differ by one word and that word was dropped — ask instead of guessing; not where that word is **every** competing pattern's first required element, since the round's winner is then [barred](../scoring.md#the-leading-required-miss-bar) and no pending opens for that set. Raises `OnCommandPending` with `PendingAmbiguity` set; the speaker answers with the distinguishing word. Off by default, because with no `OnCommandPending` subscriber an ambiguous utterance would fire nothing at all. See [Ask instead of guessing](../command-recognition.md#ambiguous-commands-ask-instead-of-guessing) |

## Properties

| Property | Type | Description |
|----------|------|-------------|
| `ActiveSetNames` | `string[]` | Names of currently active command sets. Returns the recogniser's own array rather than a snapshot copy -- treat it as read-only |
| `HasPendingCommand` | `bool` | True if a command is currently in pending state (partial match, awaiting confirmation, or awaiting disambiguation) |
| `PendingCommand` | `VoxrCommand?` | The currently pending command, or null if none. Under a disambiguation this is the candidate that *would* have fired — index 0 of `PendingAmbiguity.Choices` |
| `PendingAmbiguity` | `VoxrPendingAmbiguity?` | The ambiguity a pending command is waiting on, or null when there is no pending command or it is waiting on something else. `HasValue` is how you tell a "which did you mean?" from an "are you sure?" — see [`VoxrPendingAmbiguity`](data-types.md#voxrpendingambiguity) |

## Events

| Event | Signature | Description |
|-------|-----------|-------------|
| `OnCommandRecognised` | `Action<VoxrCommand>` | Fired for each successfully recognised command that passes threshold and debounce filters |
| `OnCommandsRecognised` | `Action<VoxrCommand[]>` | Fired with the full batch of commands extracted from a single utterance (after sequential extraction) |
| `OnUnrecognisedSpeech` | `Action<string>` | Fired when speech does not produce any accepted command -- no pattern matched, every match fell under `minScore`, a match was missing a required argument and its command does not set `allowPartialMatch` (#73), a match was diverted to a *partial-match* or *confirmation* pending, the round's winning candidate missed its **first required element** and was [barred](../scoring.md#the-leading-required-miss-bar) (#124), or follow-up speech completed a pending command whose re-score landed at or below zero and was refused (#113). **Not** fired when a match was rejected by `minConfidence`, suppressed by debounce, or diverted to a **disambiguation** pending; those three are silent. (The disambiguation case is deliberate — being told the speech was not understood in the same frame you were asked to prompt about it is the confusion the flag exists to remove.) The `string` parameter is the full buffered transcript. See [Unrecognised Speech](../command-recognition.md#unrecognised-speech) and [the gates](../scoring.md#what-onunrecognisedspeech-actually-means). |
| `OnCommandPending` | `Action<VoxrCommand>` | Fired when a command enters pending state (partial match with unfilled required slots, awaiting explicit confirmation, or — with `disambiguateSiblingTies` on — awaiting disambiguation), **and again each time follow-up speech fills some but not all of the required slots still missing** — so one pending command can raise this event several times, carrying the updated command each time. Expect one invocation per fill, not one per pending. None of the three opens for a winner [barred](../scoring.md#the-leading-required-miss-bar) for missing its first required element: the bar precedes all of them, so such a round opens no pending at any score. The payload carries no reason: read `PendingAmbiguity.HasValue` to tell which question you were asked, or you will prompt "yes/no" at a speaker who needs to say a word. See [Pending Commands](../command-recognition.md#pending-commands). |
| `OnCommandConfirmed` | `Action<VoxrCommand>` | Fired when a pending command is confirmed by follow-up speech or explicit confirmation. Also fires `OnCommandRecognised` and `OnCommandsRecognised`. **Answering a disambiguation also raises this**, carrying the chosen command — so treat it as "a pending command resolved into a fire", not as "the user approved something destructive". It does **not** raise when the chosen command sets `requiresConfirmation`: that answer identifies the intent and then asks about it, so `OnCommandPending` raises a second time instead. |
| `OnCommandCancelled` | `Action<VoxrCommand>` | Fired when a pending command is cancelled by timeout, explicit cancel vocabulary, or preemption by a new complete command. A second ambiguous utterance preempts the first question, so you will see one of these followed by a fresh `OnCommandPending`. Also fired by any call that resets pending state while a command is pending -- `CancelPendingCommand`, either `Configure` overload, `SetActiveSets` / `SetActiveSet`, and the component's `OnDisable`. |

## Methods

| Method | Signature | Description |
|--------|-----------|-------------|
| `Configure` | `void (VoxrSlotDefinition[] slots, VoxrCommandDefinition[] commands)` | Builds parser from slot and command definitions. Applies the grammar immediately when a Speech Recogniser is assigned with its model ready and `freeSpeechMode` is off -- a bare `SetGrammar` with no stop/start cycle. With `freeSpeechMode` off but the model not yet loaded it is applied as soon as the model becomes ready instead. Use for simple setups without command sets. |
| `Configure` | `void (VoxrSlotDefinition[] slots, VoxrCommandSet[] sets)` | Registers shared slots and named command sets. Does not activate any set -- call `SetActiveSets()` after. |
| `SetActiveSets` | `void (params string[] setNames)` | Activates one or more named sets, rebuilding the parser and grammar from only those sets' commands. Handles stop/set/start if recognition is running. |
| `SetActiveSet` | `void (string setName)` | Convenience wrapper for activating a single set. |
| `InjectText` | `void (string text, VoxrWord[] words = null)` | Injects text into the full command pipeline (buffer -> parser -> thresholds -> debounce) as if it arrived from VOSK. Main-thread only. Silently no-ops on null or whitespace text; logs a warning and no-ops when no parser has been built yet. With `bufferWindow` above `0` the text is buffered rather than parsed, so follow it with `FlushPendingBuffer()` -- or set `bufferWindow` to `0` -- when the parse must happen synchronously. |
| `FlushPendingBuffer` | `void ()` | Immediately flushes any speech held in the utterance buffer, forcing parse. Useful for push-to-talk release, scene transitions, and synchronous test injection. |
| `RegisterSlotValueProvider` | `void (string slotName, Func<string[]> valueProvider)` | Registers a function that controls which values of the named slot the parser accepts. Call `NotifySlotChanged()` after the provider's return set changes. The grammar is unaffected -- it always reflects the full universe of slot values. |
| `UnregisterSlotValueProvider` | `bool (string slotName)` | Removes a value provider. The slot reverts to its full value set on the next parser rebuild. Returns `true` if a provider was removed. |
| `NotifySlotChanged` | `void ()` | Rebuilds the parser to reflect current value-provider results. Does not touch the grammar or VOSK recogniser. No-op until commands are active -- before `Configure(slots, commands)`, or after `Configure(slots, sets)` until the first `SetActiveSets()`. Performs a full parser rebuild -- call only when values have actually changed. |
| `RebuildParser` | `void ()` | Rebuilds only the parser from current effective slots and active commands. Grammar and VOSK recogniser are untouched. Throws `InvalidOperationException` while no commands are active -- before `Configure(slots, commands)`, or after `Configure(slots, sets)` until the first `SetActiveSets()`. |
| `RebuildGrammar` | `void ()` | Rebuilds and re-applies the VOSK grammar from the full universe of slot values. Performs stop/set grammar/start when recognition is running. Clears the utterance buffer. Defers if a command is pending. Throws `InvalidOperationException` while no active commands exist — before any `Configure`, or after `Configure(slots, sets)` until `SetActiveSets` runs. |
| `CancelPendingCommand` | `void ()` | Cancels the currently pending command, firing `OnCommandCancelled`. No-op when no command is pending. |
