# v3.1 Phase 2: Editor Live Microphone

## Context

v3.0 (shipped as 0.10.0) added text injection — `VoskSpeechRecogniser.InjectResult()` and `VoskCommandRecogniser.InjectText()` — which covers ~80% of what developers iterate on (command definitions, slot combinations, scoring, thresholds). The remaining 20% — anything involving *actual speech recognition quality*, *VOSK confidence behavior under real audio conditions*, or *microphone gain and capture issues* — still requires a Quest 3 deploy-and-logcat cycle.

v3.1 closes that gap by adding live microphone capture inside the Unity Editor on Windows. Developers speak into the desktop microphone, audio is fed to a desktop build of VOSK, and the existing `OnFinalResult` / `OnPartialResult` / `OnResult` events fire exactly as they would on Quest. The entire `VoskCommandRecogniser` command pipeline runs unchanged against the Editor audio path.

Phase 3 of v3 (standalone Windows / PCVR runtime support) is deliberately **out of scope** and deferred to a later version — see the scope note in `v3-and-beyond-analysis.md`. v3.1 is tightly scoped to Editor testing.

---

## Scope (locked)

- **Target**: Unity Editor running on Windows only. No standalone build support, no macOS/Linux Editor support.
- **Guard symbol**: `#if UNITY_EDITOR_WIN` on all new code. If empirical testing in Unity 6000.3.7f1 reveals this symbol is not defined, fall back to `#if UNITY_EDITOR && UNITY_STANDALONE_WIN` or a runtime `Application.platform == RuntimePlatform.WindowsEditor` check.
- **Integration**: transparent — `VoskSpeechRecogniser.StartRecognition()` auto-detects Windows Editor and uses the managed backend in place of the native bridge. Existing sample scenes and user code Just Work in Editor Play Mode with zero changes.
- **Android path**: completely untouched. No refactor of the existing bridge code, `Update()` poll loop, or JSON parsing helpers. All 45/45 v3.0 tests continue to pass unmodified.
- **Public API surface**: zero additions, zero breaking changes. The transparent routing is an internal implementation detail.

---

## Architecture

C# → `libvosk.dll` directly via P/Invoke. The existing C++ `Downsampler` and `Agc` are ported to plain C# classes. No new native shim is built — `libvosk.dll` is the upstream Windows build from the alphacep/vosk-api release page.

### Data flow

```
UnityEngine.Microphone.Start(null, loop: true, 5 sec, 48000 Hz)
    ↓  (main thread polling, every Update)
AudioClip.GetData(float[], _lastSamplePos)
    ↓  (handle AudioClip ring wrap)
Downsampler.Process(float[], count, float[])     // 48k → 16k, 15-tap FIR, ported from downsampler.h
    ↓
Agc.Process(float[], count)                      // in-place, ported from agc.h
    ↓
FloatToInt16(float[], short[], count)            // *32767, clamp, cast
    ↓
VoskNative.vosk_recognizer_accept_waveform_s(recognizer, short[], count)
    ↓  returns 0 (partial) or 1 (final)
vosk_recognizer_result / vosk_recognizer_partial_result
    ↓
json string enqueued in EditorMicBackend._resultQueue
    ↓
VoskSpeechRecogniser.DrainEditorResults() dispatches via existing
ParseTextFromJson / ParseWordsFromJson / ParseAlternativesFromJson / DispatchFinalResult
    ↓
OnFinalResult, OnPartialResult, OnResult events — identical shape to Android path
```

### Why single-threaded

Per-frame work at 60 fps: ~800 input samples → ~267 downsampled samples → one `vosk_recognizer_accept_waveform_s` call. VOSK's inference cost at this chunk size is sub-millisecond on a modern desktop CPU because the acoustic model only fully evaluates at utterance boundaries. `Microphone.*` and `AudioClip.GetData` are main-thread-only in Unity anyway. A worker thread would add locking and domain-reload complexity for zero measurable win. Keep it simple: everything runs in `Update()` on the main thread.

The one exception is `vosk_model_new()` during initialisation. That call loads and parses the 50 MB acoustic model from disk and takes 1–3 seconds synchronously. `EditorMicBackend.InitialiseAsync` wraps it in `await Task.Run(...)` so the main thread doesn't hitch. This mirrors the existing `ModelExtractor.ExtractModelAsync` pattern.

## Files to create

### `Runtime/Dsp/Downsampler.cs`

Plain C# port of `NativeBridge~/src/downsampler.h`. No `#if` guard — pure math with no Unity dependencies, safe to compile on every platform (it is dead code on Android but harmless and keeps it unit-testable from the Runtime tests assembly).

- `const int DecimationFactor = 3;`
- `const int FilterTaps = 15;`
- `static readonly float[] Coefficients = { ... }` — copied verbatim from the C++ header
- `float[] _history = new float[FilterTaps];`
- `int _writePos;`
- `int _phase;`
- `public int Process(float[] input, int inputCount, float[] output)` — signature returns the number of output samples written. Caller ensures `output.Length >= inputCount / 3 + 1`.
- `public void Reset()`

### `Runtime/Dsp/Agc.cs`

Plain C# port of `NativeBridge~/src/agc.h`. Also no `#if` guard.

- `const float DefaultTargetDb = -18f;`
- `public void Configure(float targetDb, float sampleRate)` — computes the four EMA coefficients from the millisecond time constants
- `public void Process(float[] samples, int count)` — in-place, same asymmetric attack/release + tanh soft limiter as the C++ version
- `public void Reset()`
- Static helpers: `DbToLinear`, `EmaCoeff`, `FastTanh` — `MathF.Exp` / `MathF.Pow` for float-native math (avoids the `double` round-trip in `System.Math`)

### `Runtime/Native/VoskNative.cs`

P/Invoke bindings for `libvosk.dll`. Same folder as the existing `BridgeNative.cs` so all interop lives in one place. Entire file wrapped in `#if UNITY_EDITOR_WIN`.

```csharp
#if UNITY_EDITOR_WIN
using System;
using System.Runtime.InteropServices;
using UnityEngine.Scripting;

namespace VoskXR.Native
{
    [Preserve]
    internal static class VoskNative
    {
        const string Lib = "libvosk";

        [DllImport(Lib, CallingConvention = CallingConvention.Cdecl)] [Preserve]
        internal static extern IntPtr vosk_model_new(
            [MarshalAs(UnmanagedType.LPUTF8Str)] string modelPath);

        [DllImport(Lib, CallingConvention = CallingConvention.Cdecl)] [Preserve]
        internal static extern void vosk_model_free(IntPtr model);

        [DllImport(Lib, CallingConvention = CallingConvention.Cdecl)] [Preserve]
        internal static extern IntPtr vosk_recognizer_new(IntPtr model, float sampleRate);

        [DllImport(Lib, CallingConvention = CallingConvention.Cdecl)] [Preserve]
        internal static extern IntPtr vosk_recognizer_new_grm(
            IntPtr model, float sampleRate,
            [MarshalAs(UnmanagedType.LPUTF8Str)] string grammar);

        [DllImport(Lib, CallingConvention = CallingConvention.Cdecl)] [Preserve]
        internal static extern void vosk_recognizer_free(IntPtr recognizer);

        [DllImport(Lib, CallingConvention = CallingConvention.Cdecl)] [Preserve]
        internal static extern void vosk_recognizer_set_words(IntPtr recognizer, int words);

        [DllImport(Lib, CallingConvention = CallingConvention.Cdecl)] [Preserve]
        internal static extern void vosk_recognizer_set_max_alternatives(
            IntPtr recognizer, int maxAlternatives);

        [DllImport(Lib, CallingConvention = CallingConvention.Cdecl)] [Preserve]
        internal static extern int vosk_recognizer_accept_waveform_s(
            IntPtr recognizer, [In] short[] data, int length);

        [DllImport(Lib, CallingConvention = CallingConvention.Cdecl)] [Preserve]
        internal static extern IntPtr vosk_recognizer_result(IntPtr recognizer);

        [DllImport(Lib, CallingConvention = CallingConvention.Cdecl)] [Preserve]
        internal static extern IntPtr vosk_recognizer_partial_result(IntPtr recognizer);

        [DllImport(Lib, CallingConvention = CallingConvention.Cdecl)] [Preserve]
        internal static extern IntPtr vosk_recognizer_final_result(IntPtr recognizer);

        [DllImport(Lib, CallingConvention = CallingConvention.Cdecl)] [Preserve]
        internal static extern void vosk_recognizer_reset(IntPtr recognizer);

        [DllImport(Lib, CallingConvention = CallingConvention.Cdecl)] [Preserve]
        internal static extern void vosk_set_log_level(int logLevel);

        internal static string MarshalString(IntPtr ptr)
        {
            if (ptr == IntPtr.Zero) return null;
            return Marshal.PtrToStringUTF8(ptr);
            // Do NOT free ptr — VOSK owns result string memory.
        }
    }
}
#endif
```

Marshalling notes:

- `CallingConvention.Cdecl` is required. The upstream VOSK Windows DLL is built with MinGW GCC which uses cdecl for `extern "C"`. The default P/Invoke convention on Windows is stdcall, which causes stack corruption on string-returning functions if not overridden.
- `LPUTF8Str` on string parameters matches VOSK's `const char *` UTF-8 convention and the pattern already used in `BridgeNative.cs`.
- Result functions return `IntPtr` (not `string`) because the pointer is owned by the recognizer and must not be freed. Marshal via `Marshal.PtrToStringUTF8` immediately.
- `[In] short[]` for `accept_waveform_s` prevents a defensive copy-back on return.
- `[Preserve]` and `internal static` match the existing `BridgeNative` style for IL2CPP stripping safety (even though the Editor uses Mono, the attribute is harmless).

### `Runtime/EditorMicBackend.cs`

Plain class — not a MonoBehaviour, not interface-implementing. Instantiated and owned by `VoskSpeechRecogniser`. Entire file wrapped in `#if UNITY_EDITOR_WIN`.

Public surface:

```csharp
internal sealed class EditorMicBackend
{
    internal bool IsInitialised { get; }
    internal bool IsRunning     { get; }

    internal Task<bool> InitialiseAsync(
        string modelPath, float sampleRate, float micGainTargetDb, int maxAlternatives,
        Action<VoskBridgeErrorCode, string> fireError);

    internal bool Start(Action<VoskBridgeErrorCode, string> fireError);
    internal void Stop();
    internal void Reset();
    internal void SetGrammar(string grammarJson);
    internal void Release();

    internal void Tick();
    internal bool TryDequeueResult(out string json, out bool isFinal);
}
```

Internal state:

- `IntPtr _model`, `IntPtr _recognizer` — owned, freed in `Release()`
- `float _sampleRate` — passed through to `vosk_recognizer_new`
- `int _maxAlternatives`
- `Downsampler _downsampler`, `Agc _agc`
- `AudioClip _clip`, `int _lastSamplePos`, `bool _firstTick`
- `float[] _readBuffer` — sized to `_clip.samples` at `Start()` time (≈960 KB for 5 sec at 48 kHz)
- `float[] _downsampledBuffer`, `short[] _int16Buffer` — sized to worst-case per-frame output
- `Queue<(string json, bool isFinal)> _resultQueue`
- `string _lastPartialJson` — for dedup, mirrors `g_last_partial` in `vosk_bridge.cpp`

### `EditorMicBackend.InitialiseAsync` sequence

1. `VoskNative.vosk_set_log_level(-1);` — suppress VOSK's internal logging.
2. `_model = await Task.Run(() => VoskNative.vosk_model_new(modelPath));` — background thread, avoids main-thread hitch.
3. If `_model == IntPtr.Zero`, fire `ModelLoadFailed`, return false.
4. `_recognizer = VoskNative.vosk_recognizer_new(_model, sampleRate);` — fast, main thread.
5. If `_recognizer == IntPtr.Zero`, free model, fire error, return false.
6. `VoskNative.vosk_recognizer_set_words(_recognizer, 1);` — per-word confidence & timing, matches Android bridge init.
7. If `maxAlternatives > 0`, `vosk_recognizer_set_max_alternatives`.
8. `_agc.Configure(micGainTargetDb, sampleRate);`
9. `IsInitialised = true; return true;`
10. Wrap the entire try body in `catch (DllNotFoundException | EntryPointNotFoundException)` → fire `ModelLoadFailed` with message about missing `libvosk.dll` or MinGW runtime.

### `EditorMicBackend.Start` sequence

1. Guard: return `false` if `!IsInitialised` or `IsRunning`.
2. `_clip = Microphone.Start(null, loop: true, lengthSec: 5, frequency: 48000);`
3. If `_clip == null`, fire `AudioDeviceUnavailable` with a "no microphone detected" message, return false.
4. Allocate `_readBuffer = new float[_clip.samples];` and the down/int16 buffers (worst-case sizes).
5. `_lastSamplePos = 0; _firstTick = true; _lastPartialJson = null; _resultQueue.Clear();`
6. `_downsampler.Reset(); _agc.Reset();`
7. Call `vosk_recognizer_reset` to flush any residual state.
8. `IsRunning = true; return true;`

### `EditorMicBackend.Tick` sequence

Called every `Update()` by `VoskSpeechRecogniser` while `IsRunning`.

1. On first tick, validate `_clip.frequency == 48000`. If not, fire `AudioDeviceUnavailable` with the actual frequency in the message, call `Stop()`, return.
2. `int currentPos = Microphone.GetPosition(null);`
3. `int available = (currentPos - _lastSamplePos + _clip.samples) % _clip.samples;`
4. If `available == 0`, return.
5. `_clip.GetData(_readBuffer, 0)` — read the entire clip buffer. Then copy the window `[_lastSamplePos .. _lastSamplePos + available)` with modular wrap into a processing buffer. (Reading the full clip per tick is a negligible memcpy for a developer tool; it's vastly simpler than threading the wrap through every DSP stage.)
6. `_lastSamplePos = currentPos;`
7. `int dsCount = _downsampler.Process(processingBuffer, available, _downsampledBuffer);`
8. `_agc.Process(_downsampledBuffer, dsCount);`
9. `FloatToInt16(_downsampledBuffer, _int16Buffer, dsCount);` — private helper, matches the C++ `vosk_bridge.cpp:44-51` clamping exactly.
10. `int r = VoskNative.vosk_recognizer_accept_waveform_s(_recognizer, _int16Buffer, dsCount);`
11. If `r == 1`: `json = VoskNative.MarshalString(vosk_recognizer_result(_recognizer));` → enqueue as final.
12. Else: `json = VoskNative.MarshalString(vosk_recognizer_partial_result(_recognizer));` → if different from `_lastPartialJson`, update and enqueue as partial.

### `EditorMicBackend.SetGrammar` sequence

Matches the native bridge exactly (`vosk_bridge.cpp:273-308`):

1. If `IsRunning`, fire `AlreadyRunning` error, return.
2. `vosk_recognizer_free(_recognizer);`
3. If `grammarJson` is non-null and non-empty: `_recognizer = vosk_recognizer_new_grm(_model, _sampleRate, grammarJson);`
4. Else: `_recognizer = vosk_recognizer_new(_model, _sampleRate);` and re-apply `max_alternatives` if > 0.
5. If null, fire `ModelLoadFailed`, return.
6. `vosk_recognizer_set_words(_recognizer, 1);`

### `Tests/Editor/DownsamplerTests.cs` and `AgcTests.cs`

Edit Mode tests for the pure C# DSP ports. No mic, no VOSK, no DLL required.

**Downsampler tests:**
- `Process_EmptyInput_ReturnsZero` — 0 in, 0 out

**`Update`** (lines 302-361) gets an Editor branch at the top and a new `DrainEditorResults` helper:

```csharp
void Update()
{
#if UNITY_EDITOR_WIN
    if (_editorBackend != null && _isRecognising)
    {
        _editorBackend.Tick();
        DrainEditorResults();
        if (!_editorBackend.IsRunning) _isRecognising = false;
        return;
    }
#endif
    if (!_bridgeAvailable || !_isRecognising) return;

    // ... existing native drain loop unchanged ...
}

#if UNITY_EDITOR_WIN
void DrainEditorResults()
{
    while (_editorBackend.TryDequeueResult(out string json, out bool isFinal))
    {
        if (json == null) continue;
        if (json.Contains("\"error\""))
        {
            var code = ParseErrorCode(json);
            FireError(code, code.ToDescription());
            continue;
        }

        string text = ParseTextFromJson(json, isFinal);
        if (isFinal)
        {
            VoskAlternative[] alternatives = Array.Empty<VoskAlternative>();
            VoskWord[] words = Array.Empty<VoskWord>();
            if (OnResult != null)
            {
                alternatives = ParseAlternativesFromJson(json);
                if (alternatives.Length > 0 && alternatives[0].Words.Length > 0)
                    words = alternatives[0].Words;
                else
                    words = ParseWordsFromJson(json);
            }
            DispatchFinalResult(text, words, alternatives);
        }
        else
        {
            OnPartialResult?.Invoke(text);
        }
    }
}
#endif
```

`DrainEditorResults` is structurally parallel to the native drain loop (it reuses `ParseTextFromJson`, `ParseWordsFromJson`, `ParseAlternativesFromJson`, `ParseErrorCode`, `DispatchFinalResult` — all existing private/internal static methods on the recogniser). There is some duplication with the native drain, but it's small (~25 lines) and is the price of not refactoring the Android path.

## DLL download instructions

The SDK maintainer (you) downloads the VOSK Windows build and places the four binaries in `Runtime/Plugins/x86_64/`. These are committed to the repo alongside the generated `.meta` files.

1. Visit https://github.com/alphacep/vosk-api/releases
2. Download `vosk-win64-0.3.45.zip` (or the current latest Windows x64 release).
3. Extract the archive. Confirm it contains `libvosk.dll`, `libgcc_s_seh-1.dll`, `libstdc++-6.dll`, and `libwinpthread-1.dll`.
4. Copy all four files to `Runtime/Plugins/x86_64/`.
5. Open the Unity project in the Editor. Unity will auto-generate `.meta` files for each DLL — overwrite them with the YAML in this plan (or adjust the generated ones to match).
6. In the Inspector, select each DLL and verify the plugin importer shows: Editor enabled (Windows x86_64), all other platforms disabled.

If the downloaded archive ships a different set of MinGW runtime DLLs (some older releases use `pthreadGC2.dll` instead of `libwinpthread-1.dll`), update the file list in this plan and the `Runtime/Plugins/x86_64/` folder accordingly.

## Risks and open points

**R1 — `UNITY_EDITOR_WIN` symbol availability.** I have not verified this symbol is defined in Unity 6000.3.7f1. Unity's documented platform scripting symbols list `UNITY_EDITOR`, `UNITY_EDITOR_WIN`, `UNITY_EDITOR_OSX`, `UNITY_EDITOR_LINUX` (added in Unity 2019+). If 6000.3.7f1 does not honour it, fall back to `#if UNITY_EDITOR && UNITY_STANDALONE_WIN` or a runtime `Application.platform == RuntimePlatform.WindowsEditor` guard. Empirical test in the first compile will confirm.

**R2 — Calling convention mismatch.** The VOSK Windows DLL is a MinGW GCC build using cdecl. If alphacep ever ships an MSVC-built DLL, the convention changes to stdcall and string-returning functions corrupt the stack. Low probability (MinGW has been the standard for the Windows VOSK releases since the project's inception), but a `PInvokeStackImbalance` MDA exception during the first smoke test is the signal to switch to `CallingConvention.StdCall`.

**R3 — `AudioClip.GetData` wrap-around.** The implementation reads the full clip buffer per tick and indexes into it, which sidesteps wrap bugs entirely. The trade-off is a ~960 KB memcpy per frame — acceptable for a developer-only Editor tool but not something we'd want in a shipping PCVR build. The future PCVR version should re-implement this with the two-segment approach documented in the minimal plan.

**R4 — VOSK coefficient sum imprecision.** The 15-tap FIR coefficients sum to ~1.0358, not exactly 1.0, giving a ~3.5% DC gain error. The C++ version has the same issue. The DC gain test in `DownsamplerTests` should expect the actual sum, not unity gain, to avoid a false-positive test failure.

**R5 — Domain reload.** When Unity recompiles scripts during Play Mode, the script domain is reloaded and all managed state is reset. `_model` and `_recognizer` are `IntPtr` fields that survive as raw values across the reload but point to freed memory if the native bridge has been torn down. `VoskSpeechRecogniser.OnDestroy` → `ReleaseNativeResources` → `_editorBackend.Release()` should fire as part of the domain reload teardown. If it doesn't, leaked pointers will eventually crash the Editor on repeated Play/Stop cycles. Smoke test by repeatedly entering and exiting Play Mode 5-10 times.

**R6 — MinGW runtime DLL name drift.** Confirmed R6 in the minimal plan: some older VOSK Windows releases ship `pthreadGC2.dll` instead of `libwinpthread-1.dll`. Verify against the actual downloaded archive before finalizing the `.meta` files.

**R7 — Microphone permission on Windows 10/11.** Since a 2018 Windows privacy update, microphone access requires user permission in Windows Settings → Privacy → Microphone. Unity does not trigger the permission dialog automatically. The first `Microphone.Start` call may return a clip that never updates (silent) if permission is denied. Add a "no audio received for N seconds while recognising" check as a v3.2 follow-up. v3.1 documents the manual Windows permission step in the verification plan above.

## Version

This ships as **0.11.0** — new internal behaviour, no public API changes, no breaking changes. The `CHANGELOG.md` entry will highlight:

- **Added**: Editor live microphone support on Windows via transparent auto-routing in `VoskSpeechRecogniser.StartRecognition()`. Developers can test voice commands in the Unity Editor on Windows without deploying to Quest 3. Audio flows through Unity's `Microphone` API, through C# ports of the existing Downsampler and AGC, into `libvosk.dll` via direct P/Invoke.
- **Added**: C# ports of the C++ `Downsampler` (15-tap FIR, 48→16 kHz) and `Agc` (EMA level tracker + tanh soft limiter) DSP stages, with Edit Mode unit tests.
- **Added**: Windows desktop VOSK runtime (`libvosk.dll` + MinGW dependencies) under `Runtime/Plugins/x86_64/` with Editor-only plugin importer configuration.
- **Note**: Android runtime behavior is unchanged. Standalone Windows / PCVR runtime builds remain unsupported — they are a deferred future version (see `v3-and-beyond-analysis.md` scope note).
