## Bugs Addressed

All failures and bugs discovered during testing have been fixed:

1. **2.3 — Confidence threshold bypass** (BUG): Command fired with conf=0.00 below minConfidence=0.4. Root cause: `ComputeConfidence` included preamble tokens from sliding start, and threshold check used `> 0f` which skipped 0.00. **Fix**: `ComputeConfidence` now only iterates from the matched start position; returns -1f (no data) instead of 0f; threshold check changed to `>= 0f` so genuine 0.00 is rejected while -1f (no data) is skipped.

2. **3.1 — Optional literal `?a` unreliable** (VOSK limitation): VOSK heard "a" as "on" in grammar mode. Not a parser bug — "on" exists in grammar (from ApproachTarget patterns) creating phonetic ambiguity with "a". **Fix**: Removed `?a` from launch pattern in sample; "a" is already handled as a quantity slot alias (`{"a" → "one"}`), which VOSK recognizes more reliably (test 4.2: conf=0.84).

3. **7.1 — Validation missing for single-char alias keys** (gap): `RunValidationWarnings` only checked direct slot values, not alias keys. **Fix**: Added alias key validation — now warns on single-character alias keys (e.g. `Slot 'quantity' has single-character alias "a"`).
